# Двусторонний Telegram-бот поддержки

[中文](README.md) · [English](README.en.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [Русский](README.ru.md) · [العربية](README.ar.md)

Двусторонний Telegram-бот поддержки без базы данных, Google Sheets, KV и постоянного хранения сообщений. Клиент общается с ботом в личном чате, а сообщения поступают настроенным операторам или в обычные группы. Операторы отвечают клиенту через стандартную функцию ответа Telegram.

## Важно: выберите только один способ развертывания

Проект содержит **две полностью независимые реализации с одинаковыми функциями**. Развертывать обе не требуется:

```text
Вариант A: Telegram → Cloudflare Worker → Telegram Bot API / AI API
Вариант B: Telegram → Google Apps Script Web App → Telegram Bot API / AI API
```

- При развертывании только в Cloudflare Workers не нужны Google-аккаунт и Apps Script.
- При развертывании только в Google Apps Script не нужны Cloudflare-аккаунт и Worker.
- Стороны не вызывают друг друга. Внутреннего общего секрета, подписанного конверта и адреса пересылки нет.
- Корневой `config.js` — единственный файл бизнес-настроек для любого варианта.

## Возможности

- Независящий от состояния режим `round_robin` или отправка всем в режиме `all`.
- Простые списки из числовых ID, числовых строк и `@username`.
- Имя, username, числовой ID клиента, тип, время и содержимое сообщения для операторов.
- Текст, фотографии, документы, голосовые, стикеры и другие поддерживаемые сообщения.
- Разбиение длинных сообщений с сохранением подписанного маршрута ответа.
- Стандартные ответы Telegram и резервная команда `/reply ID_КЛИЕНТА текст`.
- Настраиваемые `/start` и Inline Keyboard под текстом сообщения.
- Упорядоченные ключевые правила; операторы видят и ответ, и исходное сообщение.
- OpenAI-совместимый AI вызывается только после явного `/ai вопрос` от клиента.
- Публичные HTTPS Markdown-файлы с временным кэшем на один час и без истории диалога.
- Белый список ответов в группе, подписи операторов и HMAC-защита маршрутов.
- Понятные китайские комментарии в основном коде, документация на шести языках и тесты обеих сред.

## 1. Общая подготовка

### Создание бота

Откройте `@BotFather`, отправьте `/newbot` и сохраните Bot Token. Добавьте бота в каждую группу поддержки. Каждый оператор в личном чате должен сначала открыть бота и отправить `/start`, иначе Telegram не разрешит боту писать ему.

Режим Privacy Mode не мешает получать ответы на собственные сообщения бота. Меняйте его через BotFather только при необходимости дополнительных групповых команд.

### Установка и копирование настроек

Установите Node.js 20 или новее:

```sh
cp config.example.js config.js
```

Windows PowerShell:

```powershell
Copy-Item config.example.js config.js
```

### Получение числовых ID

Попросите пользователя отправить боту `/id` или временно добавьте бота в нужную группу и отправьте там `/id`. Бот вернет ID пользователя и чата. Поддерживаются обычные группы и супергруппы; механизм тем не используется.

### Создание двух независимых секретов

Выполните команду дважды:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

- Первое значение поместите в `telegram.webhookSecret` для проверки Webhook.
- Второе — в `replies.routeSecret` для подписи маршрутов ответов операторов.

Третьего общего секрета между Worker и Apps Script не существует.

## 2. Полное описание config.js

Редактируйте корневой `config.js`. Построчные китайские комментарии находятся в [config.example.js](config.example.js).

### Telegram и Worker

| Поле | Описание |
| --- | --- |
| `telegram.botToken` | Token, выданный BotFather. |
| `telegram.webhookSecret` | 16–256 букв, цифр, подчеркиваний или дефисов. Worker проверяет заголовок, Apps Script — `/exec?secret=...`. |
| `telegram.apiBaseUrl` | Корень Telegram API, обычно `https://api.telegram.org`. |
| `worker.requestTimeoutMs` | Тайм-аут Worker для Telegram, AI и файлов знаний в миллисекундах; только Worker. |
| `worker.maxUpdateBytes` | Максимальный размер Update в байтах UTF-8; только Worker. |

### Распределение

| Поле | Описание |
| --- | --- |
| `dispatch.mode` | `round_robin` или `all`. Циклический режим использует `update_id % число целей` и не хранит курсор. |
| `dispatch.users` | Пользователи-операторы, например `[111111111, "@kefu001"]`. |
| `dispatch.groups` | Обычные группы, например `[-1001234567890, "@my_support_group"]`. |

```js
dispatch: {
  mode: "round_robin",
  users: [111111111, "@kefu001"],
  groups: [-1001234567890, "@my_support_group"]
}
```

Числовые строки преобразуются в числа, username не зависит от регистра. Для долгой работы предпочтительны числовые ID, поскольку публичные username могут меняться.

### Приветствие и Inline Keyboard

| Поле | Описание |
| --- | --- |
| `welcome.text` | Текст приветствия `/start`. |
| `welcome.buttons` | Двумерный массив строк с кнопками. |
| Кнопка `text` | Отображаемый текст кнопки. |
| Кнопка `callbackData` | Callback-значение длиной 1–64 байта; либо оно, либо `url`. |
| Кнопка `response` | Необязательный ответ клиенту после нажатия callback-кнопки. |
| Кнопка `url` | HTTPS-ссылка; либо она, либо `callbackData`. |

```js
welcome: {
  text: "Выберите услугу или отправьте вопрос.",
  buttons: [
    [{ text: "Помощь", callbackData: "help", response: "Отправьте вопрос здесь." }],
    [{ text: "Сайт", url: "https://example.com" }]
  ]
}
```

Создается `reply_markup.inline_keyboard`, а не Reply Keyboard возле поля ввода.

### Автоответы по ключевым словам

| Поле | Описание |
| --- | --- |
| `autoReply.enabled` | Включает фиксированные правила. |
| `autoReply.rules` | Упорядоченные правила; используется первое совпадение. |
| Правило `keywords` | Непустой массив; достаточно совпадения любого ключевого слова. |
| Правило `reply` | Ответ клиенту, копия которого получают операторы. |

Английский текст сопоставляется без учета регистра и по подстроке. Обычное сообщение без совпадения только передается операторам и не вызывает AI автоматически.

### AI и онлайн-Markdown

| Поле | Описание |
| --- | --- |
| `ai.enabled` | Разрешает явные запросы `/ai`. |
| `ai.apiBaseUrl` | Корень OpenAI-совместимого API, например `https://api.openai.com/v1`. |
| `ai.apiKey` | Ключ поставщика AI. |
| `ai.model` | Название модели. |
| `ai.systemPrompt` | Системная подсказка. |
| `ai.knowledgeUrls` | Публичные HTTPS URL Markdown-файлов. |
| `ai.maxKnowledgeChars` | Максимальное общее число символов знаний на запрос. |
| `ai.maxOutputTokens` | Максимум выходных Token, 1–4096. |
| `ai.temperature` | Температура выборки, 0–2. |

Читается не более 10 файлов и 50000 символов на файл, перенаправления запрещены. Apps Script использует `CacheService` на один час. Worker кэширует данные в памяти текущего экземпляра на один час и снова загружает их после удаления экземпляра. При сбое знаний или AI клиент получает уведомление, а исходный вопрос все равно передается операторам.

### Ответы и отображение

| Поле | Описание |
| --- | --- |
| `replies.groupPolicy` | `all_members` или `whitelist`. |
| `replies.allowedUserIds` | Числовые ID операторов, которым разрешены ответы в режиме белого списка. |
| `replies.showOperatorName` | Показывает имя оператора клиенту. При `false` `copyMessage` скрывает источник. |
| `replies.linkToOriginal` | Связывает ответ с исходным сообщением; после его удаления повторяет отправку без связи. |
| `replies.routeSecret` | Секрет HMAC-маршрута длиной не менее 16 символов. |
| `presentation.timeZone` | Часовой пояс IANA, например `Asia/Shanghai`. |
| `presentation.showLanguage` | Показывает язык Telegram клиента. |
| `presentation.showTimestamp` | Показывает время сообщения клиента. |

### Тексты сообщений

| Поле | Назначение |
| --- | --- |
| `messages.customerHelp` | `/help` клиента и неизвестные команды. |
| `messages.aiHelp` | `/ai` без вопроса. |
| `messages.aiUnavailable` | AI или знания недоступны. |
| `messages.invalidButton` | Недействительный или устаревший callback. |
| `messages.adminHelp` | Справка оператора. |
| `messages.unsupported` | Неподдерживаемый тип сообщения. |
| `messages.deliveryFailed` | Ошибка доставки всем целям. |
| `messages.routeNotFound` | Неверный маршрут или сообщение другого бота. |
| `messages.unauthorized` | Ответ оператора не разрешен. |
| `messages.replyFailed` | Ошибка ответа клиенту. |
| `messages.replySent` | Успешный резервный ответ `/reply`. |
| `messages.invalidReplyCommand` | Неверный синтаксис `/reply`. |

## 3. Вариант A: только Cloudflare Workers

Проект Apps Script не требуется.

### Установка, авторизация и развертывание

```sh
npm install --prefix CloudflareWorkers
npm exec --prefix CloudflareWorkers -- wrangler login
npm run sync:config
npm run deploy:worker
```

Имя Worker можно изменить в `CloudflareWorkers/wrangler.jsonc`. Достаточно бесплатного поддомена workers.dev. Скопируйте полученный `https://NAME.SUBDOMAIN.workers.dev`.

### Настройка Webhook

```sh
npm run webhook:set -- https://NAME.SUBDOMAIN.workers.dev
```

Скрипт добавляет `/webhook` и задает `telegram.webhookSecret` как Telegram Secret Token. Проверка состояния:

```text
https://NAME.SUBDOMAIN.workers.dev/health
```

Необязательно через `wrangler secret put` можно задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `REPLIES_ROUTE_SECRET`, `AI_API_KEY`. Они переопределяют созданные секреты; для самостоятельной работы переменные не обязательны.

## 4. Вариант B: только Google Apps Script

Cloudflare-аккаунт, Wrangler и Worker не требуются.

### Установка и авторизация clasp

```sh
npm install --prefix GoogleScripts
npm exec --prefix GoogleScripts -- clasp login
```

### Создание и загрузка проекта

Создайте пустой проект на `https://script.google.com/`. Скопируйте Script ID из настроек проекта или адресной строки и создайте `GoogleScripts/.clasp.json`:

```json
{
  "scriptId": "YOUR_SCRIPT_ID",
  "rootDir": "."
}
```

Загрузите самостоятельную реализацию:

```sh
npm run sync:config
npm run push:gas
```

Не редактируйте `GoogleScripts/config.generated.js` вручную.

### Публикация Web App

В редакторе Apps Script выберите **Начать развертывание → Новое развертывание → Веб-приложение**:

- Запуск от имени: **меня**.
- Кому доступно: **всем**.
- Скопируйте опубликованный URL с окончанием `/exec`, а не тестовый `/dev`.

### Настройка Webhook

```sh
npm run webhook:set -- https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
```

Apps Script не может прочитать заголовок Telegram Secret Token, поэтому скрипт добавляет `?secret=...` к `/exec`. `doPost` сравнивает значение с тем же `telegram.webhookSecret`. Не публикуйте полный Webhook URL.

## 5. Использование и проверка

1. Отправьте `/start` от клиента и проверьте приветствие и Inline Keyboard.
2. Отправьте текст, фотографию и стикер; проверьте данные клиента и содержимое у настроенных целей.
3. Ответьте на информационную карточку бота, текст с маршрутом или caption медиа; клиент должен получить ответ.
4. Проверьте `/reply ID_КЛИЕНТА текст` в чате оператора.
5. Отправьте `/id` и сравните числовые ID с `config.js`.
6. Проверьте настроенное ключевое слово; ответ должны увидеть и клиент, и операторы.
7. Отправьте `/ai Как установить?`; проверьте ответ и копию оператору. Обычные сообщения не должны вызывать AI.
8. В режиме белого списка проверьте разрешенного и неразрешенного участника группы.

```text
/start                 Приветствие клиента
/help                  Справка клиента или оператора
/ai вопрос             Явный запрос AI
/id                    Показать ID пользователя и чата
/reply ID_КЛИЕНТА текст Резервный ответ оператора
```

## 6. Обновление, тесты и устранение неполадок

После изменения настроек:

```sh
npm run sync:config
npm run test:worker
npm run test:gas
npm run build:worker
```

Обновляйте только выбранную платформу:

- Worker: `npm run deploy:worker`.
- Apps Script: `npm run push:gas`, затем в **Управление развертываниями** измените Web App, создайте новую версию и разверните ее. Обычно `/exec` URL не меняется, поэтому Webhook настраивать заново не нужно.

Устранение неполадок:

- **Webhook 401/unauthorized**: повторите `webhook:set` и проверьте развернутый `webhookSecret`.
- **Бот не отправляет сообщения**: проверьте Bot Token, журналы и сведения Telegram Webhook. Личный оператор должен сначала запустить бота.
- **Группа ничего не получает**: проверьте членство бота, отрицательный ID группы и публичный `@username`.
- **Ответ оператора недействителен**: отвечайте на сообщение бота с `R.customerId.messageId.signature`; сообщения других ботов не подходят.
- **AI не работает**: проверьте API URL, ключ, модель, HTTPS URL знаний и публичный доступ. Передача операторам продолжается.
- **Изменения Apps Script не видны**: проверьте Script ID и опубликуйте новую версию Web App.

Сообщения клиентов, диалоги, курсоры распределения и связи ответов не сохраняются. Защищайте `config.js`, созданные файлы настроек и полный Apps Script Webhook URL.
